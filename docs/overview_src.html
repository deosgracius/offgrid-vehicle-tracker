Off-Grid Vehicle Tracker

A fully off-grid system that shows a driver the direction and distance to a partner vehicle on a sunlight-readable dashboard display — no cell service, no WiFi, no infrastructure. Designed for convoy travel in remote areas such as Alaska.

LoRa radios running the open-source Meshtastic mesh firmware exchange GPS positions between vehicles; a custom-firmware display unit computes bearing and distance and renders a live navigation arrow.

1 · The Problem

Two vehicles traveling together in remote terrain routinely lose sight of each other — and with no cell coverage, there is no way to answer the basic question “where is my partner?” Existing options are a poor fit: satellite messengers are subscription-based and not glanceable while driving; phone apps need cell service; amateur-radio APRS needs licensing and equipment. The goal is a self-contained pair of devices: power them from the vehicle, and each driver sees an always-updating arrow and distance to the other vehicle.

2 · System Architecture

Each vehicle carries two devices. A Heltec WiFi LoRa 32 V4 (with GPS module) runs stock, unmodified Meshtastic firmware and broadcasts its position over 915 MHz LoRa. A Waveshare ESP32-S3 display unit with a 4.2″ reflective LCD connects to its local Heltec over Bluetooth Low Energy and renders the navigation display. The only custom firmware in the whole system runs on the display unit.

Key design decision — no Meshtastic “hacking” required. Meshtastic exposes a documented Client API: a stream of protobuf messages over BLE, serial, or TCP — the same interface its phone apps use. The device firmware already handles GPS reading, scheduled position broadcasts, AES encryption, mesh relaying, and storing each node's last known position. Our display unit simply connects as a BLE client and consumes Position packets. This turns a risky firmware-fork project into a well-scoped client application, and any third Meshtastic node in the area (e.g. one left on a ridge) automatically extends range by relaying.

3 · How It Works — Data Flow

The boundary between the two firmware halves is a single struct — the contract between the protocol module (Deo) and the UI module (Josiah), letting both develop in parallel from week 2:

struct TrackerState {
  Fix  self;      // lat, lon, course-over-ground, speed, fix_ok   (own Heltec's GPS)
  Fix  partner;   // lat, lon, age_seconds, valid                  (from mesh Position packets)
  bool ble_connected;
};

5 · Navigation: Direction & Distance

Distance comes from the haversine formula between our fix and the partner's last fix. Bearing to partner is the standard initial-bearing formula, referenced to true north:

θ = atan2( sin Δλ · cos φ₂ ,
           cos φ₁ · sin φ₂ − sin φ₁ · cos φ₂ · cos Δλ )

But the driver doesn't think in compass degrees — the arrow must point relative to the direction the vehicle is facing. We get vehicle heading from GPS course-over-ground, which is accurate above ~5 mph — no magnetometer needed (compasses are unreliable inside vehicles anyway). The arrow angle is simply:

arrow = bearing_to_partner − own_course

When stationary or very slow, the display falls back to an absolute compass rose (N/E/S/W) or holds the last good heading.

Data age is a safety feature: with 30–60 s broadcast intervals and possible dropouts, the driver must always know how fresh the fix is.

Range expectations

Vehicle-to-vehicle at ground level, realistic range is 2–8 km in open or rolling terrain — much more with line of sight, less in deep valleys or dense forest. Mitigations: roof-mounted antennas (largest single win), slower/longer-range LoRa presets, and mesh relaying.
