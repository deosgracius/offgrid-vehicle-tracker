# BLE link soak test — Aug 31, 2026 (Deo)

**Setup:** Heltec V4 (Meshtastic 2.7.26, NO_PIN, battery, window with GPS lock) +
Waveshare display (display-ble build w/ NVS persistence, commit `b689452`),
~4 m apart across a room, indoors. Link established automatically at test start
(remembered-address direct connect caught the Heltec's config-reboot window —
zero manual pairing steps). No serial/app clients touched the Heltec during the test.

**Result: PASS — zero link drops over the full afternoon.**
Evidence at test end: UI reporting `ble=1` (still connected); BLE task heartbeat
`state=3 (SUBSCRIBED), scans=0` — the scan fallback never ran, and since the
radio only accepts connections in its post-boot window (never rebooted during
the test), any drop would have left the display permanently SEARCHING. It didn't.

**Conclusions**
- The advertise-after-disconnect quirk is a **startup-only** concern in practice:
  once connected, the link holds for hours at in-cab-scale range.
- Product flow validated end-to-end: power both units → auto-connect (NVS
  remembered address) → stable link indefinitely.
- Remaining reconnect exposure: mid-drive drop (e.g., radio brown-out) requires
  a radio power-cycle. Sized by this test as a rare event; Victor's firmware
  evaluation (2.8 stable, when released) is the upstream fix.
